# 人狼「通常ルール」モードの仕様

- 決定日: 2026-09-21（ユーザー指示:「通常の人狼ゲームと全く同じものにしたい。ゲームが終わるまで続ける」）
- ユーザーが選んだ方針（質問への回答）:
  1. **ワンナイト版（いまの実装）は残し、開始時にどちらかを選べる**ようにする
  2. 役職は **村人・人狼・占い師** で始める（騎士・霊媒師・狂人は入れない。遊んでから検討）
  3. **最初の夜は襲撃なし**（占いだけ）
  4. 追放・襲撃で抜けた人の**役職は公開しない**（ゲーム終了時に全公開）
- あわせて受けた指示: **どの画面でも「いま何をする場面か」を見出しで明記する**（例: 投票は「人狼だと思う人を選ぼう」）

## 1. ルール

| 項目 | 内容 |
|---|---|
| 人数 | **4〜10 人**（3 人は通常ルールが成立しないのでワンナイトのみ） |
| 配役 | 全員に 1 枚ずつ配る（**伏せ札なし**）。人数ごとの枚数は下の表。残りは村人 |
| 勝敗 | **村の勝ち** = 生きている人狼が 0 / **人狼の勝ち** = 生きている人狼の数 ≥ 生きている人狼以外の数。追放の直後と、朝の犠牲者発表の直後に判定 |
| 1 日の流れ | 夜 → 朝（犠牲者の発表）→ 話し合い → 投票 → 追放の発表 → 夜 … を決着まで繰り返す |
| 最初の夜 | 役職の確認 + 占い師が 1 人占う。**襲撃なし**。人狼が 2 人のときは、ここで仲間の名前を知る |
| 2 日目以降の夜 | 人狼が生きている人狼以外から 1 人を襲撃。占い師（生存時）が生きている他人 1 人を占う |
| 人狼 2 人の襲撃先 | 席順で先の人狼の選択を、後の人狼は自分の秘密画面で見られる。**最終的な襲撃先は、後に操作した生存中の人狼の選択** |
| 占いの結果 | 「人狼です／人狼ではありません」の 2 値。占った相手と結果は占い師だけが見る |
| 投票 | 生きている全員が、**生きている自分以外**から 1 人を選ぶ（「人狼はいない」は無い）。単独最多票の人を追放 |
| 同票 | 同票の人だけを候補に 1 回だけ決選（全員が再投票）。それでも同票なら**その日は追放なし** |
| 抜けた人 | 以後、端末を受け取らない・投票しない・投票されない。役職は公開しない。話し合いに口を出さないのは口頭の約束（画面で案内する） |
| 話し合いの時間 | 生存人数で決める: 60 秒 + 30 秒 × 生存人数（最短 120 秒、最長 360 秒）。+1 分の延長は**その日に 1 回** |
| 時間の上限 | 1 局 120 分で無効（ワンナイトは従来どおり 45 分） |
| 終了時 | 勝った陣営、全員の役職、日ごとの記録（犠牲者・追放者・各自の投票先・占い師が占った相手と結果）を公開 |

### 1-1. 人数ごとの配役（**2026-09-21 ユーザー確認済み・決定**）

| 人数 | 人狼 | 占い師 | 村人 |
|---:|---:|---:|---:|
| 4 | 1 | 1 | 2 |
| 5 | 1 | 1 | 3 |
| 6 | 1 | 1 | 4 |
| 7 | 2 | 1 | 4 |
| 8 | 2 | 1 | 5 |
| 9 | 2 | 2 | 5 |
| 10 | 2 | 2 | 6 |

- この表は**コードでは 1 か所だけ**に書く: `core_std/werewolf_std_core.hpp` の `compositionFor()`。
  数字を変えるときは、この表と `compositionFor()` の両方を直せばよく、ほかの場所に人数分岐は無い
- **占い師が 2 人のとき**: それぞれが毎晩、独立に 1 人ずつ占う。占い師どうしは互いを知らない
  （秘密画面に仲間の欄が出るのは人狼だけ）。生きている占い師だけが占う
- **人狼が 2 人のとき**: 互いを知る（初日の夜に仲間の名前が出る）。襲撃先の決まり方は上の表のとおり
- 参考（PC 上の試験 `tools/run_wolf_std_checks.py` が出す、**でたらめに選ぶだけの**勝率。腕前は
  反映されないので構造の目安としてだけ見ること）: 4 人 村 24.9% / 7 人 村 19.3% / 10 人 村 22.4%

## 2. 回し持ち（端末 1 台）と秘密の守り方

ワンナイト版で作った仕組みをそのまま使う（`WerewolfGame.cpp` の SecretGate・中立画面の確定・見張りタスク・バックライト、`docs/WEREWOLF_TODO.md` §2-3）。

- **夜は、生きている全員が席順に同じ手順を踏む**（占い師・人狼を操作の違いから悟らせないため）:
  手渡し → 「夜の案内」（押している間だけ表示: 自分の役職 + 今夜やること。人狼には仲間の名前と仲間の選択）→
  対象を 1 人選ぶ（全員同じ画面。村人は何を選んでも何も起きない）→ 確認 → 「夜の結果」（押している間だけ表示:
  占い師 = 占いの結果 / 人狼 = 襲撃先を決めた旨 / 村人 = 何も起きなかった旨）→ 隠した → 次の人へ
- 対象選択の画面は役職で文を変えない。見出しは「夜の行動：1 人選ぼう」、注記は「効くのは占い師と人狼だけ」。
  **自分にとって何の選択なのかは、直前の秘密画面（夜の案内）で役職ごとに明記する**:
  村人「次の画面では誰かを選ぶふりをするだけ。何も起きません」/ 人狼「次の画面で、今夜おそう相手を選ぼう（初日は選ぶふりだけ）」/
  占い師「次の画面で選んだ相手が、人狼かどうか分かります」
- 抜けた人には端末を回さない（誰が抜けたかは公開情報なので、順番を飛ばしても何も漏れない）
- 朝の発表（犠牲者）と追放の発表は公開画面。「端末をテーブルに置いて、みんなで見よう」の案内を先に出す
- 秘密（配役・占い結果・襲撃先・各自の投票）は RAM のみ。NVS・SD・シリアルに出さない。統計は「1 回遊んだ」だけ
- 再起動時の「無効な局」の扱い（NVS の armed 印）は従来どおり。モードの種類は別の NVS キーに持つ
  （`public_meta.hpp` の 20 バイトは予備バイトが 0 でないと無効になるので流用しない）

## 3. 画面の見出し（いま何をする場面か）

| 場面 | 見出し |
|---|---|
| モード選択 | どちらで遊ぶ？（通常ルール：決着がつくまで ／ ワンナイト：ひと晩で決着） |
| 手渡し | ○○さんの番です |
| 夜の案内（秘密） | 今夜のあなた |
| 夜の対象選択 | 夜の行動：1 人選ぼう |
| 夜の結果（秘密） | 夜の結果 |
| 朝の発表 | 朝になりました（昨夜おそわれたのは ○○さん ／ 昨夜の犠牲者はいません） |
| 話し合い | n 日目の話し合い（残り n 人） |
| 投票 | **人狼だと思う人を選ぼう** |
| 決選 | 決選投票：候補から人狼だと思う人を選ぼう |
| 追放の発表 | ○○さんが追放されました ／ 今日は誰も追放されません |
| 決着 | 村の勝ち！ ／ 人狼の勝ち！ |

ワンナイト版にも同じ考えを入れる: 投票「人狼だと思う人を選ぼう」、夜「夜の行動：1 つ選ぼう」（注記「効くのは占い師だけ」）、
役職の説明に「次の画面はふりだけ／次の画面で占える」を明記、物語の導入に「このモードは、ひと晩で決着。襲撃も脱落もありません」を追加。

## 4. 実装の方針

- ロジックは UI から切り離した**新しい携帯可能なコア**（例 `games/werewolf/core_std/werewolf_std_core.hpp`）として作る。
  既存の `core/*.hpp`（ワンナイト・無改変で検証済み）には手を入れない。作り方は既存コアに合わせる
  （操作は版数つき・役職の配列を丸ごと返す口を作らない・秘密の読み出しは手番の本人に限る・終了時と無効時に消去）
- **PC 上で動く試験を必ず付ける**（`pip` で入れた zig をコンパイラーに使える。`docs/WEREWOLF_TODO.md` §1）:
  全人数 4〜10 の配役の数、勝敗判定、抜けた人が手番・投票・対象に現れないこと、人狼 2 人の襲撃先の決まり方、
  同票 → 決選 → 追放なし、乱数でたくさんの局を最後まで回して必ず決着すること
- 画面は `WerewolfGame.cpp` の 1 画面作り直し方式・共通部品・キャラクター表示をそのまま使い、モードで進行を切り替える
- 文言は `data/content.local.ja.json` に追加（設計書由来の JSON は書き換えない）。1 行 13 文字・秘密の本文は 4 行まで
- 物語の導入は通常ルール用の文にする（「放っておくと、常連がひと晩にひとりずつ消えていく」が、このモードでは実際のルール）
- 統計: 決着（または無効でない終了）まで進んだ局を「人狼 1 回」と数える（モードの区別は SD ログの note にだけ書く）

## 4-1. 実装したもの（2026-09-21）

- コア: `firmware/src/app/games/werewolf/core_std/werewolf_std_core.hpp`（ヘッダーのみ・C++17）
- PC 上の試験: `tools/wolf_std_checks.cpp` + `python tools/run_wolf_std_checks.py`（zig でコンパイル）
- 画面: `WerewolfGame.cpp` に通常ルールの View / Act を追加（覗き見防止の仕組みは共用・無改変）
- 文言: `data/content.local.ja.json`（`std.*` と、両モードに効く見出しの重ね書き）
- 前回選んだモード: NVS `ct_wolf` / キー `mode`（1 バイト。`meta` の 20 バイトには触らない）

### 仕様の解釈（判断したところ）

1. **見出しに名前を入れると 13 文字を超える**ため、朝の発表と追放の発表は
   「見出し＝いま何の場面か」（朝になりました／追放が決まりました）、
   「本文＝大きな名前＋何が起きたか」に分けた
2. **人狼は仲間を襲えない**。夜の対象選択の画面は全員同じ（生きている自分以外が全部押せる）で、
   人狼が仲間を選んだときだけコアが断る。仲間の名前は直前の秘密画面に出ているので迷わない
3. 決選の前に話し合いの時間は取らない（仕様書 §3 の表に無いため）。決選の候補は公開画面に出す
4. 「n 日目の話し合い（残り n 人）」は、見出しを「n 日目の話し合い」、
   下の注記を「生きている人：n 人」に分けた（1 行 13 文字に収めるため）
