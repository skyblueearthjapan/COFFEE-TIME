# JEV REVERSI 実装計画（v1・2026-09-22）

設計一式 `参考データ/ゲーム4部作/COFFEE_TIME_JEV_REVERSI_Handoff_v1.0.zip`（設計書・C++ コア・GAS 用 JS・検査・見本 `preview.html`）を読んだうえで、
**この端末の実情に合わせて何を作り、何を作らないか**を決めた記録。ユーザーから「ディレクターとして完了まで」と一任されている（2026-09-22）。

## 1. ひとことで

人間 1 人 vs AI のリバーシ。6×6（短い）と 8×8（長め）。ルール・反転・パス・勝敗はすべて端末のプログラム、
Jev は「置ける場所の一覧から 1 手を選ぶ」だけ。相手は JEV / JEV PRO / CASUAL / 端末AI の 4 種。

## 2. 設計書から変えるところ（ディレクター判断）

| 項目 | 設計書 | v1 の実装 | 理由 |
|---|---|---|---|
| GAS | 認証・冪等台帳・リース・ポーリング・複数シート・保存/再送（4 操作） | **`event:"reversi"` の 1 操作**。端末が棋譜を送り、GAS は付属の `reversi_shared.js` で局面を再計算 → Jev を呼ぶ → 検証 → 手を返すだけ | AI DUEL と同じ。端末 1 台・GAS の往復が 4〜7 秒なので、往復の回数を最小にする |
| 同じ局面の再送 | 台帳で管理 | **CacheService に「対局 ID + 手数 + 局面ハッシュ → 決めた手」を 10 分保存**。再送には同じ手を返し、Jev を呼び直さない | 設計書の意図（再送でモデルを再呼び出ししない）は守る |
| 起動時の `device.hello` | あり | なし。Wi-Fi 接続中かつ GAS の URL があれば Jev 系を選べる。だめなら理由を出して端末 AI を**本人が選ぶ** | 1 往復を省く |
| 結果の保存 | 判定つきで複数シート | 終局時に `ReversiResults` シートへ 1 行（送りっぱなし。送れなければ捨てる） | 正本は端末 |
| 遊んだ回数の保存 | 既存の 4 ゲームと同じ場所 | **カフェ機能の保存形式（`cup/today`・`cup_hist/days`）は 1 バイトも変えない**。5 つめ以降のゲームの回数は別の保存先（`cup_ext`）に持ち、画面からは同じ関数で読めるようにする | 杯数の記録がいちばん大事。ゲームのために壊す危険を取らない |
| 並び順 | 第 5 枠 | ゲーム一覧の 5 番目（AI DUEL → エスパー → 事件簿 → 人狼会 → **リバーシ**）。一覧は 5 段に作り直す | ユーザー指定の 4 つの順は維持 |

守るもの（設計書どおり）: 付属の C++ コア `reversi_core.hpp` / `reversi_session.hpp` を**無改変**で使う（検証済み）／盤面 312×312・左上 (84,84)・6×6 は 52px、8×8 は 39px／
**マスを選ぶ → 別の「置く」で確定**、確定後の待ったなし／大きい候補一覧（4 件 / 頁）／合法手を色だけで示さない・黒白とも輪郭つき／
途中の局を端末に保存して再開（294 バイト以内の `REV1` 形式）／通信障害時は本人が選べば残りを端末 AI で続行し、その局は Jev に戻さない／
Jev 不使用・混在を画面と結果で区別／Jev に送るのは盤面・手番・枚数・全合法手だけ（端末名・杯数・じゃんけんの記録は送らない）／
自動パスは 0.7 秒の表示つき／無操作 120 秒で一時停止／通信待ち・カフェへの移動を負けにしない／2 人対戦・待った・勝率表示・ヒントは作らない。

## 3. 段階

1. **第 1 段階（通信なし）**: コアの組み込みと PC 上の検査（付属の `golden_positions.json` と一致）、端末 AI で 6×6 / 8×8 を完走、
   全画面（ENTRY / サイズ / モード / 色 / 盤 / 候補 / メニュー / 確認 / 一時停止 / 結果 / 遊び方）、NVS への保存と再開、カフェ復帰、回数の記録、一覧 5 段化、履歴の表 5 行。
   この段階では JEV 系 3 モードのボタンは「準備中」。
2. **第 2 段階（Jev）**: `gas/Reversi.gs`（付属 JS を取り込み）と端末側の依頼（AI DUEL の依頼箱 `net::gasRequest` を使用）。
   待ち 12 秒で NETWORK_CHOICE（もう一度 / 端末AIで続行 / カフェ）。DETAILS 画面（最後の Jev の候補確率）。待ち時間を実測し、演出を決める。
3. 独立レビュー → 引き継ぎ書 → コミット。

## 4. 端末のデータ

- NVS 名前空間 `ct_rev`: `game`（進行中の 1 局。`REV1` 形式・294 バイト以内。1 手確定ごとに保存し、**保存に成功してから**画面を確定表示にする）、
  `stats`（盤サイズ 2 × 相手区分 5〔jev / jev_pro / casual / local / 混在〕× 勝・負・分）。
- メモリ: 内蔵メモリの余裕が小さい（TLS 1 本 約 35KB）。大きな静的配列は作らず、対局の状態は画面を開いたときに PSRAM へ確保する。

## 5. 端末 ⇔ GAS の約束（第 2 段階。`event:"reversi"`）

```json
要求: { "event":"reversi", "req":12, "snapshot": { "game_id":"<32hex>", "n":6, "human":"B", "mode":"jev|jev_pro|casual", "history":["C2:H","B2:J","PASS:F",…] } }
      （棋譜は「座標:だれが打ったか」。H=人間 J=Jev L=端末AI F=選択の余地なし〔合法手 1 つ・パス〕。付属の `CTReversi.replay` がこの形を検証する）
応答: { "ok":true, "req":12, "ply":1, "status":"ready", "move":"B2", "source":"J", "top":"B2", "p":{"B2":0.37,…}, "confidence":0.05, "ms":380, "cached":false }
      { "ok":true, "req":12, "status":"failed", "reason":"NO_KEY|PROVIDER_HTTP_429|DAILY_LIMIT|ILLEGAL_HISTORY|…" }
結果: { "event":"reversi", "req":40, "result": { "snapshot":{…}, "end_reason":"completed|resigned|aborted" } }   ← 送りっぱなし
```

- **GAS 側は 2026-09-22 に実装・デプロイ済み（@9）**: `gas/Reversi.gs` + `gas/ReversiShared.gs`（設計一式の `reversi_shared.js` を無改変で取り込み）。
  試験 `python tools/gas_call.py reversi [mode=jev_pro|casual] [same=1]`。PC からの往復 2.1〜2.7 秒、Jev 自体は 0.36〜0.38 秒。
  `top` は確率が最大の手、`move` は実際に打つ手（CASUAL ではくじ引きの結果なので `top` と違うことがある）。
- GAS は棋譜から局面を再計算し、Jev の番でなければ断る。返ってきた手が合法かは端末でも必ず確かめる（不正なら失敗扱い）。
- 1 日の Jev 呼び出しは AI DUEL と共通の上限（`JEV_DAILY_MAX`）で数える。

## 6. 検査

- `tools/reversi_checks.cpp` + `tools/run_reversi_checks.py`（zig でコンパイル）: 付属の `golden_positions.json`・セッションの保存/復元・端末 AI の手が付属の JS / Python の手本と一致すること、6×6 / 8×8 を端末 AI 同士で多数局完走（不正手 0・必ず終局）。
- GAS 側は付属の `tests/test_contract.js` 相当を Node で実行してからデプロイ。
- 実機は `tools/uiwalk.py`（**タップの前に必ず `expect:` で画面を確認**）。
