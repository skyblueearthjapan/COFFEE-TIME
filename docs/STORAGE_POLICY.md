# 保存場所の取り決め（フラッシュ / SD カード）

- 決定日: 2026-09-21（ユーザー承認済み）
- 前提: 端末は**持ち運びできるデバイス**にする予定。電源が落ちる・SD が抜けることを前提に設計する

## 1. 原則

1. **カフェ機能（カウンター・通知・時計）は SD カードなしで 100% 動くこと。** SD が抜けても壊れても止まらない
2. 置き場は「容量」ではなく「データの性質」で決める
3. **SD にしかないデータを作らない。** SD の中身は必ずリポジトリから作り直せること（ログを除く）
4. ゲーム側は置き場を直接知らない。**読み込みの窓口を 1 つ**にし、「SD → 内蔵ファイル領域」の順に探す。
   あとで置き場を変えてもファイルを移すだけで済むようにする

## 2. 置き場の一覧

| 置き場 | 大きさ | 置くもの | 理由 |
|---|---|---|---|
| アプリ領域 `app0` | 6.25 MB（2026-09-21 時点で 3.38 MB 使用） | 全ゲームのプログラム / HOME の背景・フォント / 人狼一式（フォント・文言） | RAM を使わず即表示できる。人狼は通信も SD も不要で完結させる |
| 設定領域 NVS | 20 KB | 杯数、設定値、人狼の公開メタ（20 バイト） | 小さく、電源を切っても残る。ログは置かない（小さい・書き換え寿命） |
| 内蔵ファイル領域 `spiffs` 区画（LittleFS として使う） | 3.4 MB（未使用） | 探偵以降の大きなフォント・シナリオ / 送信待ちの記録 | 抜けない。USB 経由で書き込める（`pio run -t uploadfs`）。プログラムに埋め込まないのでリンクエラーを避けられる見込み（未検証） |
| microSD | カード次第 | 操作ログ / 季節の背景・音・スクリーンショットなど「無くても動く大きなもの」 / 内蔵ファイル領域があふれたときの拡張先 | 頻繁な書き込みに向く（内蔵フラッシュへの書き込み中は画面が一瞬乱れる）。容量が大きい |
| 予備アプリ領域 `app1` | 6.25 MB（未使用） | 触らない | 将来の無線更新（OTA）用に残す |

## 3. SD に置かないもの

- Wi-Fi のパスワード・GAS の URL・合言葉（SD は持ち出せるため。`secrets.h` = フラッシュのみ）
- 人狼の配役などの秘密（設計書どおり RAM のみ）
- それが無いとカフェ機能や人狼が動かなくなるもの

## 4. SD が無い・壊れているときの動作

- カフェ機能・人狼: 通常どおり動く
- SD 上のデータが必須のゲーム・素材: メニューで「SD カードが必要です」と表示して選べなくする（落ちない）
- ログ: 書けなければ黙って捨てる（本体の動作を止めない）

## 5. 区画（パーティション）

`default_16MB.csv` のまま変更しない。OTA は「将来やるかもしれない」ため予備領域を残す。
容量が足りなくなった時点で見直す（目安: ファームが 5 MB = アプリ領域の 80% を超えたら）。

## 6. 容量の見積もり（2026-09-21 実測ベース）

- 現在のファーム 3.38 MB = 背景写真 3 枚 1.35 MB + フォント 0.63 MB（うち人狼用 445 字×3 サイズ 0.45 MB）+ プログラムほか
- 探偵の必要文字: **474 字（日本語など 409 字）で、うち 243 字は人狼のフォントに収録済み。新規は 166 字**（2026-09-21 に `required_glyphs.txt` を実測。以前の「1293 字」はファイルのバイト数の読み違い）。同じ 3 サイズに足すなら約 0.17 MB の増加見込み
- 4 作すべてで 5〜5.5 MB 程度の見込み。16 MB のうち 9 MB 以上が未使用

## 7. SD カードの配線と試験結果（2026-09-21 実機確認）

| 信号 | 接続先 |
|---|---|
| SD_CLK | GPIO2（**LCD 初期化用 3 線 SPI の SCL と共用**） |
| SD_CMD | GPIO1（**同 SDA と共用**） |
| SD_D0 | GPIO42 |
| SD_D3 | IO エキスパンダー (TCA9554) の EXIO4 = ライブラリ上のピン番号 **3**。High にしておく |
| SD_D1 / D2 | 未接続 → `SD_MMC` の **1 bit モード**で使う |

- 使う順序: `board->begin()`（LCD 初期化）→ EXIO4 を High → `SD_MMC.setPins(2, 1, 42)` → `SD_MMC.begin("/sdcard", true)`。
  LCD の CS（EXIO3）が High の間、LCD は GPIO1・2 の信号を無視する。**SD を使い始めた後に LCD へコマンドを送らないこと**
  （ライブラリの `ESP_PANEL_BOARD_LCD_FLAGS_ENABLE_IO_MULTIPLEX` は 0 のまま。アプリは初期化後に LCD コマンドを送っていない）
- 試験: `python -m platformio run -e sdtest -t upload --upload-port COM8`（`firmware/src/sdtest/`。試験用ファイルだけを作って消す。`r` 送信で再試験）
- 結果（32GB SDHC・FAT32・空）: **PASS**。書き込み 約 2.0 MB/s、読み込み 約 3.0 MB/s、1 MB の照合で不一致 0、
  ログ 1 行の追記（開く→書く→閉じる）平均 5 ms・最大 11 ms
- 目安: 背景 1 枚 (450 KB) の読み込み 約 0.15 秒、1 MB のファイルなら約 0.35 秒

## 8. 操作ログ（2026-09-21 実装・実機確認済み）

- 実装: `firmware/src/app/SdLog.*`。記録の依頼（`sdlog::event`）はキューに積むだけで、SD への書き込みは `loop()` 側の
  `sdlog::poll()` が LVGL のロックの外で行う（画面を待たせない）。1 行ごとに「開く → 追記 → 閉じる」
- 置き場: `/coffee_time/log_YYYYMM.csv`（月ごと）。時刻が分からない間の記録は `/coffee_time/log_nodate.csv`
- 列: `datetime,uptime_s,event,taken,left,prev,bat_mv,wifi,note`
- イベント: `boot`（note に `reset=poweron|software|panic|watchdog|brownout|usb|other` と `rtc=ok|lost`）/ `take` / `refill` / `newday` / `timeset`
- カードが無い・抜けた場合: 記録を捨てて動作を続け、記録が発生したときに 60 秒に 1 回までマウントを試みる。**フォーマットは絶対にしない**
- 読み方: カードを抜かなくても、シリアルで `L` を送ると今月のログの末尾（約 2 KB）が出る
  （`python tools/serlog.py COM8 5 send=L`）。HOME 下部の SD アイコンが明るければ記録中
- ゲームの秘密（人狼の配役・投票）は記録しない

## 9. 背景画像の方針（2026-09-21 ユーザーと相談・実施は人狼 W2 の後）

- 現状: 朝・昼・夕の 3 枚（各 450 KB、計 1.35 MB）をファームに埋め込み。アプリ領域は 53.7% 使用で、**今は圧迫していない**
- 方針: **フラッシュには「基本の 1 枚」だけ残し（SD が無くても HOME の背景は必ず出る）、時間帯別・季節・イベントの画像は SD に置く**。
  SD に該当の画像があればそれを使い、無ければ基本の 1 枚を表示する。フラッシュが約 0.9 MB 空き、枚数を容量の心配なく増やせる
- 形式（案）: LVGL の RGB565 生データ（480×480 = 450 KB）を PSRAM に読み込む。読み込みは 1 枚 約 0.15 秒
- あわせて検討: 朝と昼の見分けがつきにくい（全画像を明るさ 75% に落としているため）。写真の差し替え・「夜」の追加・切り替え時刻の見直し
- 先に作ると楽になるもの: **USB 経由で SD にファイルを送るツール**（カードを PC に挿し替える手作業をなくす）
