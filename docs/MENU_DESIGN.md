## 1. 原則

- **SD カードも Wi-Fi も無しで全部動く**（`STORAGE_POLICY.md` の原則 1）。グラフ用のデータは NVS に持ち、SD の操作ログは詳細の控え
- 画面は半径 228px の円内。文字は `ct_font_jp_20/22/40`、数字は `ct_font_time_64/104`、アイコンは Material Icons Round のアイコンフォント
  （人狼のキャラクターと共用。使うグリフだけ収録し、`tools/gen_fonts.sh` に追記する）
- 画面の作りは `ui::ScreenManager` に載せる 1 画面 1 関数。人狼・探偵と同じく、破棄時に静的ポインタとタイマーを必ず片付ける

## 2. 画面

### メニュー
文字の一覧 → **アイコン 4 つの 2×2**（今日の状況 / 履歴 / 設定 / ゲーム）＋「カフェへ」。

### 今日の状況
- 1 枚目: 「今日のコーヒー」/ 大きな杯数 `7 / 10 杯` / カップ 10 個のゲージ（**残っている分が明るい**。個数は「1 回に作る杯数」に連動）/
  進み具合の棒 / 「残り 3 杯」（3 以下オレンジ・0 赤。HOME と同じ色の決まり）/ 最後の 1 杯の時刻・最後の補充の時刻 /「時間ごとに見る」
- 2 枚目（時間ごと）: 今日の時間帯別の棒グラフ（表示は 8〜18 時。範囲外に記録がある日は自動で広げる）/ いちばん多い時間帯 / 合計杯数・補充回数
- 時刻が分からない間の +1 は杯数にだけ数え、時間帯のグラフには入れない（「時刻不明 n 杯」と添える）

### 履歴
- **「今週」= 月曜〜日曜**の棒グラフ（ユーザー要望。週が変わると自動で新しい週になる。今日の曜日を強調、まだ来ていない曜日は空欄）と 1 日の平均（記録のある日だけで割る）。ゲームの表の列も 今日 / 今週 / 累計
- 「30 日」表示への切り替え、日ごとの一覧（日付・杯数・補充回数、5 件ずつのページ送り）

### 設定（2 ページ・7 項目）
| 項目 | 内容 | 既定値 |
|---|---|---|
| 画面の明るさ | 10〜100%（10% 刻みのスライダー）。その場で反映 | 100% |
| 画面を暗くする | 触らない時間が続いたら暗くする: 1 分 / 5 分 / 10 分 / 30 分 / しない。暗い間の最初のタッチは**復帰だけ**（ボタンを押したことにしない） | 5 分 |
| 時刻を合わせる | 時・分の上下ボタン、日付の変更。決定でシステム時刻と RTC に保存、SD ログに `timeset`。Wi-Fi 接続時は NTP が優先 | — |
| 操作音 | オン / オフ（公開画面のタップ音。人狼の秘密画面では鳴らさない） | オフ |
| 1 回に作る杯数 | 5〜15 杯。補充したときの LEFT とゲージの個数 | 10 |
| ~~朝いちばんの残り~~ | **項目から外した（2026-09-21 ユーザー確認）**: 朝は必ず 0 杯から始める運用（夜の残りは配るかアイスコーヒーにする）なので、日付が変わったら LEFT は常に 0 杯。名前も意味が伝わらなかった。保存形式の欄は残してあるが使わない | — |
| Wi-Fi | 状態の表示のみ（接続中か・電波の強さ・登録数）。名前とパスワードは表示しない | — |
| システム情報 | 電池の電圧と目安 %、Wi-Fi の強さ、SD の空き、時計の状態（NTP 同期 / RTC / 未設定）、前回の起動の理由と経過時間、ソフトの版（ビルド時の Git の版） | — |

## 3. データの持ち方（NVS）

| 名前空間 / キー | 中身 | 書き込む時機 |
|---|---|---|
| `cup` / 既存の `ymd` `taken` `left` | 変更なし | 従来どおり |
| `cup` / `today`（blob） | 版、日付、時間帯別の杯数 `uint8[24]`、時刻不明の杯数、補充回数、最後の 1 杯・最後の補充の時刻 | +1・補充のたび（既存の保存と同じ時機にまとめて） |
| `cup_hist` / `days`（blob） | 直近 35 日の輪。1 日 = 日付 `uint32` + 杯数 `uint16` + 補充回数 `uint8` + 予備。版と CRC 付き、書いたら読み返す | **日付が変わったとき 1 回**（前日の確定値を追加）。電源が入っていなかった日は欠番のまま |
| `cfg` / `v1`（blob） | 明るさ、暗くするまでの時間、操作音、1 回に作る杯数、朝いちばんの残り。版と CRC 付き | 設定を変えたとき |

- 壊れている・版が違うときは既定値で始め、杯数（`cup`）には影響させない
- 杯数の上限は `CupState` の `kMaxCups`（定数）から設定値へ変える。読み込み時の丸めもそれに合わせる

## 4. 既存の処理への影響（実装時の注意）

- **バックライトの持ち主を 1 か所にする**。新しく `display::`（仮）を作り、明るさ・暗転・復帰をここだけが行う。
  人狼の覗き見防止（`WerewolfPort` の `cutBacklight/restoreBacklight` と見張りタスク）は、復帰のとき **100% ではなく設定の明るさ**に戻すこと。
  **ゲーム画面が出ている間は自動の暗転をしない**（読み物の途中や秘密の受け渡し中に暗くならないように）
- **1 回に作る杯数を変えると通知メールのゲージとずれる**（`gas/Code.gs` の `MAX_CUPS = 10` が定数）。端末から `max` を送り、GAS は届いた値を使うように
  する（GAS は `clasp -u work push` → `update-deployment`。URL は変えない）。GAS を直すまでは端末側の値だけが変わる
- **操作音**: ブザーは IO エキスパンダーの EXIO8（I2C 経由）なので、音程を変える PWM はできない見込み。鳴らし方（オン時間）を実機で確認してから入れる
- **ソフトの版**: PlatformIO の `extra_scripts` でビルド時に `git rev-parse --short HEAD` を取り、`-DCT_GIT_REV` として渡す（変更ありなら `+` を付ける）
- 開発用シリアルコマンド: 新しい画面を直接開くコマンドを足し、`tools/uiwalk.py` で全画面を撮って確認する
- 日本語を足したら `python tools/collect_ui_chars.py` → `bash tools/gen_fonts.sh`（HOME 用とゲーム用のフォントは統合しない）
