## 1. 企画の中心：正解の先に、人物を知る

### 1.1 プレイヤーの役割

プレイヤーは喫茶「余白」の常連になりかけた「手帳の持ち主」。警察官でも、客を追及する取り調べ役でもない。小さな行き違いを整理し、人を責める代わりに理由を知る。

冒頭の初回案内は固定：

> ここは、喫茶「余白」。小さな不思議を、手掛かりからほどくお店です。うまく解けなくても大丈夫。物語は、最後までつづきます。

物語のコピー：**「当てるために疑うより、分かるために話を聞こう。」**

### 1.2 二つの答えを混ぜない

- **採点する答え**：誰が置いたか、誰が作ったか。公開証拠から一意に定まる。
- **結末で知ること**：なぜ置いたか、誰を迎えたかったか。これは推測させて採点しない。

動機を知らなければ解けない後出し、店主の人柄だけで選ぶ正解、雨や表情から根拠なく犯人を当てる演出は禁止。

### 1.3 感情の流れ

| 話 | 最初の気持ち | 推理の楽しさ | 最後に分かる人物の一面 |
|---|---|---|---|
| 1 二つのカップ | 注文は一杯なのに？ | 時刻と順番をつなぐ | 無口なチャイが、誰かを迎えようとしていた |
| 2 青い封筒 | 名前がない小さな手紙 | 色・印・人物を結ぶ | 落ち着いたラテも、誘うときは照れる |
| 3 雨上がりのしおり | 記憶が食い違う | 一つだけ違う発言を特定 | モカは失敗役ではなく、思い出を直して渡す人 |

ミスを笑う話を三回続けない。全員が正直とは限らない問題でも、間違いを悪意や性格に結び付けない。

### 2.1 舞台設定

喫茶「余白」は、窓際に二脚、カウンターに数席、壁に小さな伝言棚のある架空の店。具体的な市区町村や実在店舗を設定しない。毎話、閉店前や夕方の短い出来事を扱う。ゲーム内の時計と天候は脚本のもので、COFFEE TIME HOMEの実時刻・実天気で変えない。

毎回同じ三か所を見せ、場所への親しみを作る。

|---|---|---|---|

### 2.5 レパートリーの拡張方針

初期3話をまずプレイテストする。次章の下記は企画メモにとどめ、実装データには入れない。

- 注文票の余白：同じ数字に見えるが、時刻と杯数を区別する話。
- 窓の向こうの傘：持ち主の取り違えを、模様と置き場所から整理する話。
- 二枚目のレシート：誰かのおごりではなく、別々の注文が重なった話。
- 開かない伝言箱：開錠技術ではなく、届け先の順番を確かめる話。
- 店休日の花：誰が飾ったかと、なぜ営業日でない日に飾ったかを分ける話。
- 一文字だけ違う招待状：誤植を責めず、誰向けの文面だったかを見つける話。

追加時は「謎の構造」「物語の味」「人物の役割」を同時にローテーションする。名前と数字だけの差し替えを新しい事件数に数えない。未完成の話を選択可能にしない。

## 3. 完成するゲーム体験

### 3.1 基本の流れ

`HOME → GAME → CAFE DETECTIVE → 本人/ゲスト（既存共通UI） → 話を選ぶ → 導入 → 今回の約束 → 捜査（証拠3つ） → 手帳で整理 → 推理 → 人物選択 → 決定確認 → 答え合わせ → 論理の解説 → 結末 → 手帳の記念品 → HOME`

メニューに全3話を表示する。未読のうち番号が最も小さい話を「次のお話」として先頭で勧めるが、強制ロックはしない。各話は独立して解ける。後の話を先に開く場合は「前の話の結末に触れます。読む」を1回確認。毎日新作があると偽らず、「今日の新作」ではなく「次のお話」とする。

### 3.2 選べるモード

| mode | 内容 | 条件 |
|---|---|---|
| solo | ひとり推理。AI回答も勝率も出さない | 常時利用可 |
| jev | 同じ情報をJevに渡し、最後に比較 | 実API検証、通信、キー、利用枠が全て有効 |
| solo_practice | オフラインまたは復習のローカル対戦 | 個人の正式な初見記録には統合しない |

`practice`はmodeと別の属性。オンラインでも答えを一度見た話はpractice。初回でもヒント使用は`assisted=true`。モードを裏で偽装しない。

### 3.3 結果の全組合せ

| 人間 | Jev | 初見・無ヒント時の表示 |
|---|---|---|
| 正解 | 不正解 | あなたの勝ち！ |
| 不正解 | 正解 | AIの勝ち！ |
| 正解 | 正解 | どちらも名探偵！ |
| 不正解 | 不正解 | 今回は、どちらも未解決 |

ヒントあり・復習・ゲスト・通信障害・AI不在・コミット検証失敗では正式な勝敗へ数えない。両者の答えを比較表示できる場合も「参考比較」とする。人間だけの正誤と物語閲覧は有効。Jevの答えを難易度調整のために書き換えない。正解が多く引き分けばかりでも、物語が成立することを中心にする。

### 3.4 ポイント・手帳・再挑戦

初見の正解2点、ヒント付き正解1点、不正解/答えを見る0点。点は本人向けの記録で、反射神経や読書速度による加点なし。復習のポイントは画面内の参考値だけで累計に加算しない。章の最大点は6だが公開順位を作らない。

記念品は結末の最後まで読んだ全員に与える。正解の報酬と混同しない。3つで章の記念ページを開く。何度遊んでも記念品は重複しない。

- 第1話：青いカップ。
- 第2話：青い招待状。
- 第3話：銀色のしおり。

間違えた人物に対応した短いフィードバックを先に出し、その後に全員共通の正解解説を出す。間違いでも結末を短縮しない。

### 3.5 ヒントと「答えを読む」

各話2段階。レベル1は考え方、レベル2は一歩進んだ整理。段階を飛ばさない。一度読んだフラグは戻る操作でも消さない。オンラインではサーバーがhint_levelの保存を確定してから本文を見せる。通信で保存できなければ、その場で表示せず「練習として読む」へ切り替える。

「答えとつづきを読む」は全証拠を読まなくても利用可。確認後、`human_choice=null,gave_up=true`で結果を固定する。AI勝利に数えない。解説と結末は通常と同じ。

### 3.6 コーヒー操作を邪魔しない

全捜査・結果画面の左上に「カフェ」ボタンを置き、共通カフェパネルへ戻れる。パネルには既存「コーヒー＋1」「ゲームへ戻る」「HOME」がある。＋1は既存の冪等イベントIDで記録し、ゲームの点数・seen_ids・attempt_idとは独立する。

コーヒー操作後の「ゲームへ戻る」は元のページ。ネット待ち中でもパネルを開ける。ゲームを理由にタッチ/UIスレッドを止めない。読書中180秒無操作でブックマークを保存して一時停止し、本人情報を隠す。読書中の60秒で突然ログアウトさせない。メニュー/結果放置60秒なら共通ログアウト。

## 4. 問題の論理仕様

### 4.1 「今回の約束」は世界のルール

第1・2話は証拠と証言が正確という前提。第3話だけ、3発言のうち一つが誤りという前提。登場人物の印象では判定しない。

第1話の約束は、3訪問時刻が既知、一人1回、同時訪問なし、青カップは訪問中に置かれ、途中で他人が触らず、置いた後動かされないこと。これがなければ時刻だけから置いた人は決まらないので省略禁止。

第2話の色と印は一人一つずつ重複なし・完成後入替なし。第3話の「置いた人＝誤った発言者」とは限らない条件も省略禁止。

### 4.2 全探索による検査

付録の`DetectiveCore.solve()`はモデル推論を使わず、有限の割当てを全列挙する。

| 話 | 構造的に許される世界 | 条件を全部満たす世界 | 正解 |
|---|---:|---:|---|
| CD001 | 18（人物の順番6×青カップの時刻3） | 1 | CHAI |
| CD002 | 36（色の割当て6×印の割当て6） | 1 | LATTE |
| CD003 | 3（置いた人の3候補） | 1 | MOCHA |

全57の構造的候補を調べる。all_differentで落とす前の直積の数とは違う。CD001の生直積は81、CD002は729、CD003は3。

第1・2話は証拠カードを1枚ずつ外した6ケースで、答えが複数になることも検査する。第3話は「発言が三つ」というルールごと成立するので、同じ除外テストを無理に適用せず、3候補×3発言の真偽表を確認する。

### 4.3 安全な式データ

`var/lit/eq/lt/not/and/exactly_false`だけを許可する。任意JavaScript、eval、Function、外部URL参照、ファイル参照は不可。再帰32階層、直積100,000まで。未知の演算子はエラーで止める。

論理表が正しいだけで日本語の意味まで自動検証できたことにはしない。人が全文を読み、量化（ちょうど1人、誰も）、時刻区間、否定、指示語の対応を編集チェックする。第19章の真偽表/割当表と本文を突き合わせる。

### 4.4 出題データの変更

一文字の見た目調整はcontent_versionを変更。答え、約束、証拠、選択肢、Jev入力に影響する変更はquestion_versionも増やす。変更前の挑戦は旧版で完結させる。ゲーム途中で新しい証拠へ差し替えない。現行と一つ前のパックを最低24時間保持し、参照が残る場合は削除しない。

## 6. 脚本データ・公開情報・秘密情報

### 6.1 著作用パック

`data/catalog.author.json`には世界名、人物、3話のpublic/privateを収録する。各話のpublicには導入・約束・質問・3選択肢・証拠3つ・ヒント2段階・背景小話・メニューコピー。privateには全探索式・正解・誤答別文・解説・結末・手帳アイテム・編集注記。

`public`という著作側の名前は、その全項目をネットで無条件配信する意味ではない。特にヒントは初見オンラインでは別の認可付きAPIで取得する。`DetectiveCore.publicCase()`の許可リストだけが配信用の正本。

### 6.2 三つの配布物を分ける

| 配布物 | 宛先 | 含めるもの |
|---|---|---|
| authorパック | 管理者・ビルド処理・GAS採点側 | 全部 |
| publicパック | オンラインの捜査用端末、Jev入力ビルダー | 約束・証拠・候補・導入。正解・ヒント・結末・論理表なし |
| soloパック | オフライン練習用Flash・PC参考版 | 全部。ただし技術的に答えを見られることを明記 |

オフライン版に正解が必要な以上、改造した端末からの攻略を完全には防げない。暗号化したから絶対分からないとは説明しない。社内の気軽なゲームとして運用し、正式な賞金競争へ使わない。オンラインの通常APIに不必要な秘密を漏らすこととは別問題として対策する。

### 6.3 IDと文字列の取り扱い

- case_id：CD001〜CD003。人名はLATTE/MOCHA/CHAI/COCOA。候補には3人だけ。
- clue_id：各話内E1/E2/E3。常にcase_idと組み合わせて扱う。
- ページ位置：sectionとclue_idと0始まりpage_index。サーバーは該当配列長で検証する。
- 文字列はUTF-8。日本語をHTMLとして評価しない。PC参考版はtextContent、端末はlv_label_set_text。
- 日付や時計の表示は現実のタイムゾーンでよいが、本文の17:48等を変えない。
- カタログは完成データを凍結し、ユーザー入力で文字列や規則を上書きしない。

### 6.4 日本語フォント

UTF-8の文をFlashへ保存しただけでは表示できない。`tools/build_package.js`が全データから必要文字を抽出する。抽出物は**文字一覧であってフォントファイルではない**。使用権限を確認した既存日本語フォントから、実装担当の環境で22/24/28px等の必要グリフを生成する。フォントバイナリーは本納品に含めない。[S13]

人名登録で許した文字とゲームグリフを同じものと仮定しない。プロフィール描画は既存フォントを利用。サロゲート・半角英字・全角記号・改行、最長ページを実機試験する。表示不可の文字があれば四角い豆腐のままリリースしない。

## 8. Jevの責任と実API

### 8.1 何をさせるか

Jevには「この事件の条件を満たす人物は誰か」というChoiceを一つだけ聞く。脚本生成、動機の創作、正解判定、嘘の追加、ヒントの即興生成はさせない。公式のChoiceは選択・確率分布・confidenceを返す。[S03][S04]

本書の初期モデル指定は、調査時公式に掲載されていた`jev-1.13.0`。`jev-latest`へ自動追従しない。利用権限と日本語問題での結果は実キーで試験する。Jevが短い推理に必ず正解すると保証しない。[S05][S06]

### 8.2 正式HTTPと構造

```text
POST https://api.typesafe.ai/v1/systemone
Authorization: Bearer <Script PropertiesのJEV_API_KEY>
Content-Type: application/json
```

リクエスト本体は`{model,state,questions:{answer:{type:"choice",instructions,criteria}}}`。stateは公開の導入文、約束、全証拠の本文と手帳まとめ、質問。criteriaは3人のID→名前説明。完全な生成処理は`modelRequest()`であり、別の未確認URLや架空のSDK関数を作らない。[S03][S04]

**送信禁止**：private全体、answer_id、solver、真偽表、ヒント、正解解説、結末、前話の正解、選択済み人物、読んだ順番、迷った時間、プロフィール、PIN、メール、天気の現在地。本人の手掛かり閲覧順をAIへのヒントにしない。

日本語UIの証拠をそのまま送る。英訳を付ける場合は別prompt_versionで試験し、人間にも同じ意味が表示されているか編集確認してから切り替える。AIだけに簡略化した正解直結の論理式を与えない。

### 8.3 応答検証

`answers.answer.type`がchoice、choiceが三つのいずれか、probabilitiesのキー集合が厳密に三候補、各値が有限0〜1、和1±0.001、choiceの確率が最大と1e-6以内、confidenceが有限0〜1。丸め誤差だけ再正規化する。modelは指定版と一致させる。usageは取得できれば非負整数、なければnull。HTML、不明な候補、文字列の数値、負値は不正応答。

勝敗を整えるために正解IDへ補正しない。confidenceは確率分布から作られる指標で、本人との対戦勝率や実測正解率とは別。画面の確率は「AIの予測」、confidenceは必要なら詳細画面だけ。通常結果は候補確率の丸め整数を表示し、100になるよう最終1項目を調整する場合も内部の値は保存したままにする。[S07]

### 8.4 AIを確定するタイミング

全証拠を読んで「推理する」を押した時にprepareを開始。準備中は候補の選択・送信を許可しないが、証拠の読み返しとカフェ操作は可。AIの選択と分布を保存し、コミットハッシュを受け取ってから人物三択を有効化。

1attemptにつきアプリケーションからのJev呼出しは最大1回。過去の問題での結果をキャッシュして使うモードはv1に入れない。再送や再ログインで推論をやり直さない。API内部の課金処理まではexactly onceと保証しない。

### 8.5 コミット文字列

```text
"CAFE_DETECTIVE_COMMIT_V1\n" + canonical_json({
 attempt_id,case_id,question_version,public_hash,generation,
 model,choice,probabilities,confidence,nonce_hex
})
```

canonical_jsonは再帰的キーの辞書順、JSONの数値・文字列、配列順維持、空白なし、UTF-8。nonceは32byte相当の64hex。サーバー秘密を使うHMAC等で予測不能に作る。3候補だけの裸のhashでは総当たりできるためnonceを省略しない。tokenやPINは文字列に含めない。

AI確定時のSHA-256を端末が受け取り、答え合わせでchoice/probabilities/model/nonceと確定generationを受け取って検証する。GASはハッシュ対象のUTF-8文字列そのものを`commit_payload`として保存し、resolved後だけ返す。ESP32はその**文字列のバイト列**からSHA-256を計算する。浮動小数の再シリアライズ差を避けるため、ArduinoJson等で再出力したJSONをハッシュしない。ハッシュ一致後、payload内のattempt/case/版/public_hashを保存済み期待値と比較し、AI表示は検証済みpayloadのchoice/probabilitiesから作る。外側のai_revealとの値が違えばエラー。番号をincrementした後のgenerationと取り違えない。`publicAttempt()`はresolvedまでAI選択・分布・nonceを返さない。

ハッシュは「一度示した値を後から変えた」ことの検出用で、悪意あるサーバー管理者のあらゆる不正を防ぐ証明ではない。不一致なら正式勝敗は除外し、物語は続ける。

### 8.6 接続できない場合

401/403はキー・権限を管理記録し新規Jevを停止。400/422は契約不一致として停止。429は利用枠のクールダウン。5xx・タイムアウト・不正応答はその話をsoloへ切り替える。生の秘密付きHTTP本文をログに残さない。現行UrlFetchAppにはtimeoutSecondsがあるので参考値8を指定するが、GAS起動・Sheets保存を含む全体8秒保証ではない。[S08]

Jevの代わりに採点用の全探索を動かして「AIも正解」と出さない。`今日はAIがお休みです。ひとり推理で、物語を続けましょう。`と表示する。遅れて返った推論は、そのgenerationの有効なpreparing中でない限り破棄する。

## 9. 状態遷移と保存の正本

### 9.1 挑戦の状態

`investigating → preparing → ready → resolved`がJevモード。soloはinvestigating→ready→resolved。任意の未決着状態からabandoned/expiredへ移れる。`paused`はphaseとは別のbooleanで、戻っても証拠・ヒント・AIの確定を失わない。

| 操作 | 前提 | 結果 |
|---|---|---|
| begin | 有効本人/guest、パック一致 | investigating。初見/復習をサーバー確定 |
| progress | 未決着・未pause | 既読IDをunion、cursor更新 |
| hint | 未決着・未pause | hint_levelを単調増加。表示より先に保存 |
| prepare | 全証拠既読 | soloならready、Jevなら予約preparing |
| provider commit | 同じgeneration、lease内 | ready＋隠した予測＋公開ハッシュ |
| timeout/failure | 未確定preparing | solo ready。遅い結果は不採用 |
| resolve answer | ready、全証拠既読、hash一致 | 回答固定、正誤、初見記録、解説公開 |
| resolve null | 未決着・未pause | 答えを見る。初見消費、勝敗対象外 |
| pause | 未決着 | paused=true。device/actorの操作リースを解放 |
| resume | 本人、同一device、有効期限内 | リース再取得、paused=false |
| abandon | 未決着 | abandoned。結果・解説は公開しない |
| finish | resolved | story_completed、記念品。二重加算しない |

finishはstory_completedとrevisionだけを更新し、generationを増やさない。resolve時のcommitted_generationを安定させるためである。返すPublicAttemptにはサーバーアダプターがcursor/story_completed/first_eligibleを許可リストで追加し、state_jsonを丸ごと返さない。

expires_atは開始から24時間の絶対期限。`now >= expires_at`で期限切れ。get/pollで延ばさない。期限前に確定したresolved結果は、期限後も保存期間内は照会できる。

### 9.2 初見の扱い

主キー`player_id + case_id + question_version`でCDProgressを1行持つ。答えが公開された最初の瞬間にfirst_exposure_at_msとfirst_result_attempt_idを設定する。最初の不正解・ヒント付き・答えを見るを消して「初見」をやり直さない。前に解説を見た場合は新しい挑戦をpracticeにする。

まだ答えを見ずに中断しただけなら初見候補のまま。同じ本人の同じ問題に未完attemptを複数作らず、既存を再開または明示的に終了する。異なる端末へ自動で引継がない。

soloでもオンライン本人の初見正誤/ポイントは保存可能。ただしJev勝敗統計はnull。guestはサーバー内部でpractice=trueとし、全体の正式集計に混ぜない。

### 9.3 一話の途中で別の人が使う

「あとで読む」でcursorを保存→pause→共通logout。次の人は自分のプロフィールで別のattemptを開始できる。前の人のカード・結果をそのまま見せない。元の人の再認証で同一deviceのpaused attemptを再開する。

preparingでpauseした場合、既に動いている1回の推論はlease内なら保存してよい。画面は更新しない。次回再開で同じ確定回答を利用する。結果待ち中のsession失効を理由に再推論しない。

### 9.4 二重送信の優先順位

認証と所有権→既存request_idの照合→終端結果の照合→expected_revisionの検証→状態変更。既にresolvedで同じanswerなら、異なる新request_idでも保存済み結果を返し集計しない。違うanswerはANSWER_ALREADY_LOCKED。

BUSYやpreparingの暫定状態を不変の最終レスポンスとしてCDRequestsへ固定しない。receiptにはresource_refを保存し、再照会で現在の安全な公開状態を組み立てる。response_safe_jsonへtoken・隠したAI答えを保存しない。

## 10. ESP32→GAS APIの全契約

### 10.1 共通HTTP

既存Apps Script Web Appの`/exec`へJSON POST。namespace=`cafe_detective`だけを新ルーターへ渡す。他namespaceとコーヒー処理の挙動は維持する。Script PropertiesやspreadsheetのURLを端末表示に含めない。

```json
{
  "namespace":"cafe_detective",
  "api_version":1,
  "action":"attempt.resolve",
  "request_id":"11111111111111111111111111111111",
  "device_id":"22222222222222222222222222222222",
  "device_token":"<登録端末token>",
  "player_token":"<本人の期限付きtoken>",
  "created_at_ms":1790000000000,
  "sent_at_ms":1790000000000,
  "payload":{
    "attempt_id":"33333333333333333333333333333333",
    "expected_revision":5,
    "answer_id":"CHAI",
    "public_hash":"<64hex>",
    "commit_hash":"<64hex、soloではnull>"
  }
}
```

例のID/時刻/hash/tokenは形式説明であり、実在する接続情報ではない。全IDは生成した32hex、public_hash/commit_hashは計算した64hex。未知キー、型違い、8KiB超過はBAD_REQUEST。JSON.parse失敗を空オブジェクトにしない。

- sent_atはサーバー時刻±5分。device.helloだけ未同期0を許可。TLS検証は省略しない。
- created_atから48時間超の更新はREPLAY_TOO_OLD。照会は新request_id。
- 再送はrequest_id/created_at/payloadを変更せず、再認証したtokenとsent_atだけ更新可。
- 指紋はcanonical `{namespace,action,device_id,actor_id,payload}`のHMAC-SHA256。秘密はScript Propertiesの専用鍵。プロフィール用の平文PINは当namespaceのAPIへ送らない。
- GASイベントに任意Authorizationヘッダーがあると仮定しない。端末認証はHTTPS本文。JevのBearerキーはGAS内だけ。[S09]

### 10.2 レスポンス

```json
{
 "namespace":"cafe_detective","api_version":1,
 "request_id":"11111111111111111111111111111111",
 "server_time_ms":1790000000300,"ok":true,
 "data":{"attempt":{}},"error":null
}
```

失敗時は`ok:false,data:null,error:{code,retryable,retry_after_ms}`。コードの日本語文は端末の固定表から出す。バックエンドのstack trace、Sheets ID、APIキーを出さない。ContentServiceに存在しないsetStatusCodeを捏造せず、アプリケーションエラーはJSONで表す。HTTP200だけで成功判定しない。[S09][S10]

### 10.3 全15操作

payloadの型・必須キーは`data/api_contract.json`、成功時dataの全フィールドは`data/api_responses.json`が正本。全キー必須、null許可が書かれたものだけnull可。一覧：

| action | 処理/返答 |
|---|---|
| device.hello | 端末認証、時刻、対応版、利用可否。本人token不要 |
| catalog.list | 3話の題名・版・public_hashだけ。解説・進捗なし |
| episode.get | 指定版のpublicCase。ヒント・結末なし |
| attempt.begin | 初見/復習を確定して一話開始。既存未完はATTEMPT_ACTIVE＋認可済みID |
| attempt.get | 状態/cursor。resolved時だけ結果/解説/結末 |
| attempt.progress | seen_idsをunion、cursorを検証して保存。通常は推理前にまとめて1回 |
| attempt.hint | 段階を保存してからヒントページを返す |
| attempt.prepare | 推論枠予約→1回呼出し→確定。Jev不能ならsolo。詳細は第11章 |
| attempt.resolve | 選択固定と正誤記録。nullなら答えを見る |
| attempt.pause | cursor保存、paused、操作リース解放 |
| attempt.resume | 同一deviceで再認証後再開。リース競合ならBUSY |
| attempt.abandon | 明示的な終了。答えは見せない |
| attempt.finish | 結末を読み終えた記録と記念品。resolvedのみ |
| profile.progress | 本人の各話の初見/復習/読了/記念品 |
| profile.exposure | オフラインで答えを読んだ事実を反映。正式勝敗や点は加算しない |

`cursor.section`はintro/rules/clue/notebook/ambient/choice/result/explain/ending/collectible。clue/ambientでは該当IDを指定し、それ以外null。page_indexは実データの範囲内。ending等はresolved以外拒否する。

### 10.4 result_contentの全構造

```text
result_content = {
 feedback: string|null,          // 不正解選択に対応した固定文
 explanation: Page[],           // 全員共通の根拠
 epilogue: Page[],              // 物語の結末
 collectible: {id,label,text},
 ai_reveal: null|{
   prediction:{choice,probabilities,confidence,model,usage},
   nonce_hex,committed_generation,commit_payload
 }
}
Page = {speaker: CharacterId, emotion: neutral|puzzled|soft|smile, text: UTF8}
```

resolved時だけ返す。作者のsolver/author_noteは結果後も端末APIに不要なので返さない。返答は64KiB以内。必要な場合も本文を途中で切るのではなく、release前にパックサイズを検査する。

### 10.5 全エラーの処理規則

- 認証系：DEVICE_UNAUTHORIZED/AUTH_REQUIRED/AUTH_FAILED/ACTOR_DISABLED→本人情報を隠し認証へ。ゲームの答えは変えない。
- データ系：BAD_REQUEST/UNSUPPORTED_VERSION/CASE_NOT_FOUND/CASE_VERSION_MISMATCH/PUBLIC_HASH_MISMATCH→勝手な変換をせず更新・設定確認。
- 競合系：REQUEST_CONFLICT/REVISION_CONFLICT/ATTEMPT_ACTIVE→getで状態照会。別人の結果を流用しない。
- 操作系：EVIDENCE_REQUIRED/HINT_ORDER/NOT_READY/BAD_CHOICE/BAD_CURSOR→現在UIを修正し、ローカルで条件を捏造しない。
- 終端系：ATTEMPT_EXPIRED/ATTEMPT_CLOSED/ANSWER_ALREADY_LOCKED→保存済み結果か、新しい練習への案内。
- 安全系：COMMIT_MISMATCH/STORAGE_UNCERTAIN/MAINTENANCE→正式集計停止。物語は練習で継続可。
- 一時系：BUSY/RATE_LIMITED→指定待ち時間後に同じ操作またはget。無限リトライ禁止。
- その他：INTERNAL_ERROR→固定の安全な日本語。詳細は機密除去済み管理ログのみ。

### 10.6 Googleの返答リダイレクト

ContentServiceの返答はgoogleusercontentの一時URLへリダイレクトされ得る。[S10]

ESP32は認証JSONをscript.google.comの設定済みURLへPOSTし、302/303のLocationがHTTPSで許可したGoogle応答ホストかを確認。そのURLへは**GET・本文なし・token再送なし**で返答を取得する。最大3段。accounts.google.comのログインHTML、未知ドメイン、HTTP降格、秘密本文を再POSTする307/308は自動許可しない。

実際のArduino HTTPClient/IDFクライアントでこの動作を試験する。`setInsecure()`で解決しない。Google Workspaceが匿名Web App呼出しを禁じる場合、管理者に無断で公開設定を緩めず、承認された既存経路へ適合させる。

## 11. Googleスプレッドシート保存・同時実行・復旧

### 11.1 配置

既存のゲーム用非公開Workbookを使う。全社員へ共有されたコーヒー集計ファイルにPINや個人結果を追加しない。今回追加するゲームタブは同一Workbook内の6種類。型・列順は`data/sheets_schema.json`の完全配列。未使用列を現場判断で足さない。

| タブ | 主キー | 用途 |
|---|---|---|
| CDMeta | key | schema、行番号割当、利用上限、操作リース等 |
| CDCatalog | case_id + question_version | 配布可能な版とpublic_hash。本文/正解はGAS配布データから読む |
| CDAttempts | attempt_id | 一話一挑戦の状態と結果スナップショット |
| CDProgress | player_id + case_id + question_version | 初回露出/初回結果/読了/記念品 |
| CDRequests | device_id + request_id | 48時間の再送照合 |
| CDAudit | event_id | 設定変更・移行・削除・異常復旧 |

既存DuelPlayers/DuelSessions/DuelDevicesを共通本人確認アダプターから読む。個人登録・PINをもう一組作らない。本ゲームのhistory_resetとDUELのhistory_resetは別の明示操作。全ゲーム削除は共通管理操作として両方へ反映する。

### 11.2 フィールドの意味

- CDMeta `schema_version`,`pack_version`,`next_row:<tab>`,`day_budget:<JST日付>`,`lease:device:<id>`,`lease:player:<id>`など。値はJSON。秘密鍵を入れない。
- CDCatalog statusはactive/retired。既存attemptが使う旧版は期限と保持条件を満たすまでGASデータから消さない。
- CDAttempts state_jsonは第9章の全状態＋cursor＋story_completed＋first_eligible。外側のID/phase/revisionと一致させる。UTF-8 16,000byte以下というアプリ側上限。state_hashはcanonical stateのSHA-256。
- CDProgress first_result_jsonは最初の結果だけ。後の復習で上書きしない。correct、points、assisted、gave_up、provider、comparisonを記録。初回情報がない場合null。
- CDRequestsは秘密を含まない業務レスポンスかresource参照。ログインtokenを保存しない。preparingの一時値はresponse_kind=resourceとする。
- CDAuditのoperator_idはGoogle認証された管理操作の識別情報。プレイヤーのPINやAPI入力全文は記録しない。

### 11.3 SheetsをDBのように使う際の制約

Google Sheets `spreadsheets.batchUpdate`は同一リクエスト内の更新を原子的に適用するが、外部の共同編集までロックするものではない。[S11]

全ゲーム書込みは**一つのGASプロジェクトの共通ストア**を通す。getScriptLockはプロジェクト内の排他で、別GASプロジェクトや手編集を防がない。[S14] 当該タブへの手入力/並べ替え/行挿入/数式は禁止し、管理者用集計は別タブ。

`Sheets.Spreadsheets.batchUpdate`（高度なSheetsサービス）を用い、updateCellsで明示的な行番号へ絶対値を書く。appendRowを複数呼んで「全体が原子的」と見なさない。新行位置はCDMetaのnext_rowから予約し、行作成とnext_row更新を同じバッチに含める。先頭ヘッダーは検査し、違えば止める。

### 11.4 一回のresolveの原子的範囲

1. 共通script lock取得。認証と所有権、receipt、phase/revision/hashを確認。
2. CDAttemptsのresolved行、必要ならCDProgressの初回結果、CDRequestsのreceipt、CDMetaの行割当/操作リースをメモリー上で完成させる。
3. 一つのbatchUpdateへ全て入れる。文字列はuserEnteredValue.stringValue、数字はnumberValue。名前の先頭`=`を数式実行しない。
4. 保存確定後だけokを返す。終端結果を再送で再計算・再加算しない。
5. finallyでlockを解放。

参考`sheets_plan.js`は書込み配列の作成のみ。実際の認証・ヘッダー検査・行割当・下記barrierは実装担当が追加する。

### 11.5 保存成否が不明なときのbarrier

GAS→Sheetsのタイムアウトは「書かれていない」ことの証拠ではない。batch送信前に、Script Propertiesへ小さな`CD_STORAGE_BARRIER_JSON`（op_id、request_key、対象行、予定state_hash、開始時刻）を設定する。鍵や本文は入れない。

- 正常応答と対象receiptの整合確認後にbarrierを消す。
- 成否不明ならbarrierを残し、**同じストアに対する全ゲーム更新**を止める。既存DUEL/共通認証の書込み経路にもこのbarrier確認を追加して回帰試験する。
- getは保存済みreceiptとstate_hashを照合。既に一度だけ適用済みと確認できれば、追加書込みなしで保存済み結果を返せる。
- receiptが見えない場合、即座に「未適用」と判定しない。自動で別行へappendしない。管理者が実行中処理の終了と対象行を調べるまでfail closed。
- 不一致のある部分状態は勝手に修復しない。Google側で原子的適用されたはずの範囲に不一致があるなら、手編集・版混在・実装不備を疑い管理復旧する。

同じbarrier方式のDUELが既にあるなら共通ストアへ統合し、独立した二つのロックで安全だと見なさない。本書は任意の分散障害で完全なexactly onceを保証するものではない。危険な推測より停止を優先する。

### 11.6 prepareと外部APIの分離

```text
lock取得
  認証/状態/全既読/枠/古いrequestを確認
  generation++、preparing、lease=now+20s、provider_call_reserved=trueを保存
lock解放
  予約を取った実行だけJevを1回呼ぶ（8秒設定）
lock再取得
  最新attemptを読み、同generation/preparing/lease内か確認
  有効ならreadyとして予測とcommitを保存
  無効なら遅い結果を捨てる
lock解放
```

外部API待ちでlockを保持しない。復旧実行はJevを再呼出しせず、lease終了時にsolo readyへ進める。別のrequestのprepareでも予約済みなら同じresourceを返す。pause中に結果が来ても同generationなら保存できる。abandon/resolve/expire後は採用しない。

### 11.7 実行上限と保守

v1のアプリ側上限は、端末あたりJev準備3回/分、全体100回/日。GoogleやTypeSafeの契約上限を意味しない。キーなしなら使用0。公開Web Appなので端末認証に加えて先に枠を確認し、外部呼出しを乱発させない。

Google側には実行時間・外部fetch・同時実行などの制約がある。クォータは変更され得るので配備時に公式値と契約アカウントを確認する。[S15][S16] シート全列全履歴を毎操作読み込まない。キャッシュは索引ヒントに使えても、正本/ロック/初回判定に使わない。

日次保守は期限切れattempt、guestの24時間、receiptの48時間、個人明細の90日を処理。個人の読了/初見集計は本人の削除まで保持する初期方針。90日を超える結果は集計だけにし、個々の推論分布を残さない。削除は対象行のクリア/状態化とし、他の索引を壊す物理行詰めは管理移行時だけ。

## 12. 個人プロフィール・プライバシー・ゲーム共通化

### 12.1 共通アダプターの契約

既存AI DUELのプロフィールが実装済みなら、次のインターフェースへつなぐ。未実装ならまずguestで物語を作り、本人機能は共通認証実装後に有効化する。氏名を選ぶだけで本人結果を返してはいけない。

```text
resolveCoffeeActor(device_id, device_token, player_token)
  → {actor_id, player_id_or_null, is_guest, device_id, expires_at_ms, enabled}
```

端末tokenは端末ごと32byte以上の秘密、サーバーにはそのダイジェスト。本人tokenは有効期限/失効/deviceとの結び付きを確認。既存案のニックネーム＋6桁PINは取り違え防止の簡易認証であり、業務機密の強い認証と同じではない。PIN検証、試行制限、再設定は共通のAI DUEL認証実装に集約する。CAFE DETECTIVE APIにはPINフィールド自体を作らない。

共通プロフィールの既定契約：PIN平文保存なし、個別salt＋秘密pepperによる検証、本人5回失敗で15分停止、端末15分に10回で停止、token20分・RAMのみ、履歴閲覧は本人認証後。これらを新たな未検証のパスワード方式へ作り直さない。

### 12.2 記録するもの/しないもの

記録する：話ID・版・初見か・回答候補・正誤・ヒント段階・読了・記念品・provider・保存時刻。未完のcursor/既読IDは再開用として保持し、完了後の分析目的には使わない。

記録しない：顔、声、実在の職務評価、迷いの秒数、タッチの細かい軌跡、キャラクター閲覧順による性格推定。Jevへ本人IDを送らない。事件の結果から社員の知能/誠実さを推定しない。

### 12.3 削除・リセット

本人の希望を管理UIで確認し、CAFE DETECTIVEだけの記録リセット、または全ゲームの本人削除を別操作として提供。公開doPostに管理者の削除actionを追加しない。削除開始でsession失効/active attempt停止→対象progress/attempt/receiptの個人参照を削除→完了監査。バックアップの扱いも管理者に表示し、バックアップ復元で削除済み個人を復活させないため削除台帳を適用する。

### 12.4 端末再起動

tokenはRAMだけなので電源断後は本人の再認証が必要。NVSにはrequest_id、attempt_id、cursor、public_hash、未送信answer等の最小復旧情報を保存し、PIN・Jevキー・本人tokenを置かない。未送信answerは共有端末でセンシティブな業務情報ではないが、別人へ表示しない。

guestは再起動で前sessionを復元しない。旧guestを期限処理し、ローカル練習または新guestとして開始。本人は再認証→getでサーバー正本を照合してからUIを再開する。

## 13. オフライン・電源・中断

### 13.1 通信が切れたとき

捜査中は既に取得した本文をそのまま読める。正式モードの答え送信が必要な時だけ接続を試みる。結果が不明なまま別answerに変えない。

ローカル練習へ切り替える場合は「正式な対戦記録には入りません」を明示する。端末にあるsoloパックで正誤・解説・結末を処理し、`offline_exposure`をジャーナルへ記録。復旧時は正式attemptを勝手にresolvedへ変換せず、get→必要ならabandon、profile.exposureで答えを見た事実と読了のみ登録する。

正式submitを既に送信済みで成否不明なら、まずgetで結果を確認する。オフライン側の別回答で上書きしない。既にサーバーresolvedならその結果が初見正本、ローカルは復習扱い。露出同期が済むまで同じcaseのオンライン初見開始を禁止し、再挑戦はpracticeにする。

### 13.2 ジャーナル方式

設定と別namespaceに二つのスロットA/Bを持ち、`format_version,sequence,crc32,payload`を保存。新スロットを書いて読み返し、妥当な最大sequenceを選ぶ。複数キーが一括原子的だと仮定しない。書込み中電断の試験が必須。

各ページめくりでFlashへ書かない。証拠カード終了、ヒント受領、送信確定直前、一時停止、結果確定、結末終了を保存ポイントとする。直前のページ位置だけが失われた場合は最後の保存位置へ戻り、見ていない扱いのページが少し重複することは許容する。投票の二重確定やヒント解除は許容しない。

### 13.3 電力方針

バックライトは読む間の見やすさを優先し、既存の輝度設定を使う。ネット接続や日本語描画が増えた分の持続時間は実測する。1500mAhだから必ず一日動くとは表示しない。電池残量の換算が未検証なら数値％を出さない。

初期版ではdeep sleep復帰を新規に必須実装しない。タッチでバックライト復帰する際、復帰に使った最初のタップを回答確定にも使う二重動作は避ける。真のsleep復帰可否は基板配線と既存実装を確認する。

````python
"""Extract the embedded source files from the specification. No code is executed.
Usage: python extract_from_md.py specification.md new_empty_output_dir
"""
from __future__ import annotations
import hashlib
import re
import sys
from pathlib import Path, PurePosixPath

PATTERN = re.compile(r'^<!-- BEGIN_FILE path="([A-Za-z0-9_./-]+)" sha256="([a-f0-9]{64})" -->\n````[a-zA-Z0-9]*\n(.*?)^````\n<!-- END_FILE -->$', re.M | re.S)

def extract(source: Path, destination: Path) -> int:
    # read_bytes preserves the exact LF endings protected by the block digest.
    raw = source.read_bytes().decode('utf-8')
    blocks = PATTERN.findall(raw)
    if not blocks:
        raise ValueError('No embedded file blocks found. Do not use a reformatted copy.')
    if destination.exists() and (destination.is_symlink() or any(destination.iterdir())):
        raise ValueError('Use a new or empty output directory; existing work will not be overwritten.')
    seen = set()
    verified = []
    for relative, digest, body in blocks:
        p = PurePosixPath(relative)
        if p.is_absolute() or any(x in ('', '.', '..') for x in p.parts) or relative in seen:
            raise ValueError('Unsafe or duplicate relative path: ' + relative)
        seen.add(relative)
        data = body.encode('utf-8')
        if hashlib.sha256(data).hexdigest() != digest:
            raise ValueError('Digest mismatch (possibly altered line endings): ' + relative)
        verified.append((p, data))
    destination.mkdir(parents=True, exist_ok=True)
    base = destination.resolve()
    for p, data in verified:
        target = destination.joinpath(*p.parts)
        if not target.resolve().is_relative_to(base):
            raise ValueError('Path escapes destination: ' + str(p))
        target.parent.mkdir(parents=True, exist_ok=True)
        target.write_bytes(data)
    return len(verified)

if __name__ == '__main__':
    if len(sys.argv) != 3:
        raise SystemExit('Usage: python extract_from_md.py specification.md new_empty_output_dir')
    try:
        count = extract(Path(sys.argv[1]), Path(sys.argv[2]))
    except (ValueError, OSError, UnicodeError) as e:
        raise SystemExit('Extraction stopped: ' + str(e)) from e
    print(f'Extracted and SHA-256-verified {count} files. No code was executed.')
````
